# Jim brief: manual workflow to generate city-directions JSON in CI

**For:** Jim (bug-fix / product mode). This brief authorises a new `.github/workflows/` file.
**tim-review:** no

## Problem
`public/city-directions/<city>.json` is generated by `scripts/write-city-directions.mjs <city>`
against live feeds, and `qa/bundled-city-directions.mjs` requires it for every live city.
Claude sandboxes can't reach many feeds (proxy 403), so the Copenhagen flip PR #454
(branch `flip-copenhagen-live`) is stuck without `copenhagen.json`. GitHub Actions runners can
reach those feeds.

## Do
1. Add `.github/workflows/write-city-directions.yml`, triggered by `workflow_dispatch` only.
   Inputs: `city` (string, required) and `branch` (string, required). Guard it so it refuses
   `master`/`main`; it only commits to an existing feature branch.
2. Steps: check out `inputs.branch`, set up Node 22, `npm ci`, run
   `node scripts/write-city-directions.mjs ${{ inputs.city }}`, then run
   `node qa/bundled-city-directions.mjs`. If `public/city-directions/<city>.json` changed, commit
   only that file as github-actions[bot] ("Generate city-directions/<city>.json in CI") and push
   to `inputs.branch`. Set `permissions: contents: write` at job level. No other files may be
   committed: check with `git status --porcelain` and fail if anything else changed.
3. Pass through the env keys the script might need from `secrets.*` (e.g. `NTA_API_KEY`,
   `VIC_OPENDATA_API_KEY`, Trafiklab keys). Check `lib/providers/registry.js` `envKeys` for the
   full set. Missing secrets are fine for cities that don't need them.
4. Note: a push made with GITHUB_TOKEN does not trigger CI on that branch. Document that the PR
   then needs one more push, or a manual `ci.yml` workflow_dispatch if ci.yml supports it (check).
   If ci.yml has no workflow_dispatch, add one. That's a one-line, safe change.
5. Document the one-click usage in `docs/multi-city-provider-design.md` or a short
   `docs/city-directions-workflow.md`.

## Acceptance
- The YAML parses, and the workflow is manual-only.
- `node qa/run-all.mjs --smoke` passes, apart from named environmental failures.
- The PR links this brief. No background loops.

## Round 2: Mark QA FAIL on PR #455 (26 Sep 2026). Fix on the same branch `jim/city-directions-workflow`
1. **Script injection.** `${{ inputs.city }}` and `${{ inputs.branch }}` are pasted directly into
   `run:` in 4 places: the refuse-master step, the generate step, the diff-guard step and the push step.
   Map them once via `env:` (`CITY`, `BRANCH`) and use `"$CITY"`/`"$BRANCH"` everywhere.
   Add an early validation step: CITY must match `^[a-z0-9-]+$`, and BRANCH must match
   `^[A-Za-z0-9._/-]+$`, contain no `..` and not start with `-`. Otherwise fail with `::error::`.
2. **Single-file guard does substring matching.** `grep -v -F "$expected"` treats any porcelain
   line *containing* the path as expected (e.g. `<city>.json.bak`). Parse each line's path
   (`${line:3}`; for a rename `old -> new`, take both sides) and compare it for **exact** equality
   with `public/city-directions/$CITY.json`. Anything else fails the job.
Everything else passed: manual trigger, main/master refusal, `--only=` flag, secrets through env, docs.
