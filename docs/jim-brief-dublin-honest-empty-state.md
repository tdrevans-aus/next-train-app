# Jim brief — honest empty state for live stations with no real-time predictions (Dublin flip prerequisite)

**Lane:** bug-fix / product mode. **Scope:** shared rider-facing board UI + Dublin coverage copy + Mark's checklist. **City lock:** ireland (Dublin coverage.json/dogfood edits). **Date:** 27 Sep 2026. **tim-review: approved in chat 27 Sep 2026** — Tim: "Yes, do the honest empty state and flip Dublin." That approval covers the rider-facing copy below.

## Problem
NTA's GTFS-RT TripUpdates intermittently omit a stop's stopTimeUpdate rows for minutes at a time while service runs (Red Cow empty for ~5 min, then served for ~10, then empty again together with Kylemore; Kingswood served throughout). Evidence: docs/dublin-d1/jim-handoff.md 27 Sep entry on branch `origin/jim/dublin-red-cow-gap` (commit 7383b32) — merge that branch into yours first so the findings land with this PR. Under the live-only rule the adapter correctly returns zero trips, but the rider sees a blank board indistinguishable from "app broken". Connolly (permanent gap) is already filtered out (#478); Red Cow must stay — it is served 21/31 polls.

## Fix
1. **Shared UI (public/):** when a LIVE city's `/api/board` returns a well-formed board with zero trips for every direction AND the response indicates service should be running (`nextServiceDate` is today / `scheduleSource` is live-empty — inspect what the board/next-train responses already carry; add a small explicit field on the server if needed, e.g. `emptyReason: "no-live-predictions"`, without changing `/api/next-train`'s existing fields), render the empty-state title: **"No live predictions for this stop right now"** and body: **"Trains are running but the operator's live feed has no times for this stop at the moment. Try again in a minute or check a nearby stop."** For Dublin the word is "trams", so make the vehicle noun come from the city's mode (train/tram/metro) — reuse whatever the app already uses for mode-aware copy. Do NOT show this for: planned/retired cities (existing 501 path), feed errors (existing "Live times are temporarily unavailable" 503 path), outside service hours (existing next-service copy), or a station that simply has no trips in one direction while other directions do (only the all-directions-empty case).
2. **Dublin coverage:** lib/cities/dublin/coverage.json — add a rider-facing note: "The NTA live feed sometimes has no times for a stop for a few minutes; the app says so rather than showing a blank board." Keep the Connolly notCovered entry.
3. **Sweep semantics:** qa/dublin-all-stations-live-sweep.mjs — an empty station is acceptable ONLY if the rider-facing `/api/board` for it would trigger the honest empty state (assert the field/shape you added), and never for more than N consecutive polls (N=3 at 30 s) for the same station; Connolly excluded already.
4. **Mark's checklist:** append one paragraph to docs/live-flip-checklist.md: for GTFS-RT cities, run the all-stations live sweep; an empty in-catalog station passes only with the honest empty state present; a permanently empty station is filtered out with a coverage note (Connolly precedent). Mirror one sentence in .claude/agents/mark.md.
5. **Browser QA:** `qa/honest-empty-state.mjs` (fixture-stubbed `/api/board` with an all-directions-empty live response) asserts the title/body render, and that the three excluded cases above do NOT render it. Register in qa/run-all.mjs smoke tier.
