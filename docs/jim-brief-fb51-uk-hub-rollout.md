## Why (two problems, one mechanism)

1. **Rider's hub vs printed terminus** (the Kidderminster case): a through service runs past the hub riders anchor on, to a terminus they don't recognise. Fix = curated hub chip fetched via Darwin `filterCrs`/`filterType=to` (calls-at semantics).
2. **Sparse results at fan-out hubs** (the backlog's Nottingham/Derby example): every Darwin region fetches 15 undirected rows then filters client-side to one chip, so a busy hub shows 0–1 trains per direction. Fix = the *exact-chip* path: fetch `filterCrs=<destination CRS>` server-side. In West Midlands this only fires when the destination resolves in the **region** catalog. In East Midlands most chips are out-of-region termini (London St Pancras, Norwich, Liverpool Lime Street), so it never fires. Hence the national index below.

## Design

### 1. Shared helper — `lib/cities/uk/direction-hubs.js` (new)

Move the four pure functions there, parameterised by `regionId`, loading `lib/cities/<regionId>/direction-hubs.json` when present and returning `{ hubs: [] }` when the file is absent (a region with no hub file behaves exactly as today). Keep `lib/cities/uk-west-midlands/direction-hubs.js` as a thin re-export so nothing in West Midlands changes; its gate must stay green unmodified.

Also move `planUkWestMidlandsNextTrainFetch` there as `planUkNextTrainFetch(entry, mode, destination, hubs, { regionId, resolveDestinationCrs })`. Same decision table:

| Chosen destination | Result |
|---|---|
| Matches a hub `label` for this station | `{ kind: "hub", filterCrs }` |
| Chip whose destination part resolves to a CRS (region catalog first, then the national index) | `{ kind: "exact", filterCrs, operatorMatch: true }` — keep trips whose `directionChip(trip) === destination` |
| Anything else | `{ kind: "undirected" }` |

`mode !== "train"` is always undirected. Metro/NET never consults hubs.

### 2. National name→CRS index — `lib/cities/uk/rail-crs-index.json` (generated) + `scripts/build-uk-rail-crs-index.mjs`

One-time generated file from `fetchRailReferencesCsv()`: `{ "<normalised name>": "CRS", ... }` for every GB station, plus a small alias table for how Darwin prints termini that differ from RailReferences (at minimum: "London St Pancras (Intl)" → STP, "Liverpool Lime Street" → LIV, "Birmingham New Street" → BHM, "Manchester Piccadilly" → MAN, "Stansted Airport" → SSD, "Leeds" → LDS, "Sheffield" → SHF, "Norwich" → NRW, "Cardiff Central" → CDF, "Edinburgh" → EDB, "Plymouth" → PLY, "Corby" → COR, "Lincoln Central" → LCN, "Crewe" → CRE, "Leicester" → LEI, "Nottingham" → NOT, "Derby" → DBY). Normalise the same way `chipDestinationPart()` does (strip the ` (Operator)` suffix, case-fold, drop punctuation). Record the generation date in the file. Unresolvable names fall through to undirected — never guess.

Validate with a token-free QA script (`qa/uk-rail-crs-index.mjs`): every printed terminus in the chip sets above resolves; a nonsense name does not; the index has > 2,000 entries.

### 3. East Midlands — `lib/cities/east-midlands/direction-hubs.json` + wiring

Wire `getEastMidlandsDogfoodDirections` / `getEastMidlandsDogfoodNextTrain` through the shared helper the same way West Midlands is (post-process chips; plan → hub/exact/undirected fetch; `printedDestination` on remapped trips). Proposed v1 hub table — **you verify every row live with `--filter-crs` before writing it, Tim approves in the PR**:

| label | filterCrs | appliesFrom | absorbs (printed destinations) | why |
|---|---|---|---|---|
| Nottingham | NOT | ALF, CHD | Nottingham, Norwich | Liverpool–Norwich (EMR) and Leeds–Nottingham (Northern) both call at Nottingham from Alfreton/Chesterfield; riders anchor on Nottingham. Collapses the "Nottingham (EMR)" / "Nottingham (Northern)" operator split too. |

Do **not** add hubs at Nottingham Station, Leicester, Kettering or Wellingborough: their chips are genuine termini riders recognise, and the sparse-results problem there is fixed by the exact-chip path, not by a hub. If probing shows another real case, list it in the PR as a proposal, unadded.

Expected effect at Nottingham Station (record before/after in the PR): choosing "London St Pancras (Intl) (East Midlands Railway)" fetches `filterCrs=STP` and returns a full board instead of 0–2 rows from the undirected 15.
