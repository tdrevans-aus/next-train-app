# Melbourne (Metro Trains + V/Line) station catalog

Dogfood catalog for `lib/providers/melbourne.js`. **Not** wired to product UI (picker entry
stays `comingSoon: true` until Mark/Tim flip `status: "live"` in `lib/providers/registry.js`).

- `stopIds` are GTFS `stop_id`s for the platform-level (location_type blank) child stops of
  each named station, generated by `scripts/generate-melbourne-stations.mjs` from
  `docs/melbourne-d1/published-network.json` and the Metropolitan Train (folder 2) static GTFS
  feed. Real trips.txt/stop_times.txt rows call at these platform child ids, never at the
  location_type=1 parent id directly.
- Requires server env `VIC_OPENDATA_API_KEY` (header `KeyID`, never client / git). Register at
  https://opendata-signup.transport.vic.gov.au/.

Feed (Transport Victoria Open Data Portal):

- Static schedule (zip-of-zips; folder 2 = Metropolitan Train, folder 1 = V/Line regional):
  https://opendata.transport.vic.gov.au/dataset/gtfs-schedule — republished to the
  next-train-gtfs Vercel Blob store by `scripts/publish-melbourne-gtfs-to-blob.mjs` (never
  fetched live on the request path; the raw statewide zip is ~293MB).
- Metro trip updates: `.../gtfs/realtime/v1/metro/trip-updates`
- V/Line trip updates: `.../gtfs/realtime/v1/vline/trip-updates`

This supersedes the earlier PTV Timetable API v3 (HMAC devid+key) path — that key never
arrived (tracker: Blocked since 29 Aug 2026). See `docs/melbourne-d1/jim-handoff.md`.
